# Render test deployment with Cloudflare DNS

Render runs the FastAPI backend as a Python web service. `render.yaml` describes a Render Free web service; it does not create the service or change DNS by itself.

## Before deployment

- Use a test MySQL database that is reachable from Render. The application reads `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, and `DB_PASSWORD` from its environment. Configure the database provider's network rules for Render's outbound addresses and use a database account with only the permissions the app requires.
- The Blueprint enables `DB_SSL_ENABLED=true` and asks for `DB_SSL_CA_PEM`, which verifies the MySQL server certificate and hostname. For Aiven MySQL, paste the **complete CA certificate contents** from the Aiven service's Overview → Connection information into Render's `DB_SSL_CA_PEM` environment variable; never paste passwords or connection strings into chat. Update it when Aiven rotates its CA. Ask the database provider for the correct hostname, port, and network rules; do not disable certificate verification to bypass a connection error.
- Before deploying, point the local backend `.env` at the intended **test** database, check for duplicate tenant slugs as described in `backend/README.md`, and run `cd backend` followed by `.\.venv\Scripts\python.exe -m alembic upgrade head`. Do not run migrations against a production database without reviewing and backing up its data first. The service does not automatically migrate databases on startup.
- The app's rate limits use the client address supplied by Uvicorn. Behind Render and Cloudflare, validate the trusted proxy configuration before production; otherwise customers can share one proxy's limit. Do not trust arbitrary forwarded headers or set `--forwarded-allow-ips='*'`. Use shared rate-limit storage if running multiple server instances.

## Create the Render service

1. Put this project in a Git repository and connect it to Render. Do not commit `.env`, `.venv`, or database credentials.
2. In Render, create a Blueprint from the repository's root `render.yaml`. Enter the requested database environment variables in Render; set `DB_PORT` if your provider uses a port other than 3306. `SECRET_KEY` is generated by Render and must remain stable across restarts.
3. Wait for the build and deployment to finish. Verify `/healthz` and `/docs` on the provided `onrender.com` URL. Test a published shop at `/v1/api/public/menus/<existing-slug>`.

### Existing service configured in the Render dashboard

If the service was created manually, `render.yaml` does not automatically update its settings. In the Render dashboard, select the Python runtime and set **Root Directory** to `backend`. Set the build command to:

```sh
pip install -r requirements.txt
```

Set the start command to:

```sh
python -m uvicorn main:app --host 0.0.0.0 --port $PORT
```

In the service environment settings, set `PYTHON_VERSION=3.13.2` and `SERVE_FRONTEND=false`. Set the database settings and a stable, random `SECRET_KEY` as described above; a local `.env` and `ca.pem` are not uploaded. Remove `DB_SSL_CA_FILE` and set `DB_SSL_CA_PEM` to the full Aiven certificate. Deploy the updated source and verify `/healthz` and `/docs`. If the service is Blueprint-managed, synchronize the Blueprint instead.

## Connect `*.sabrey.xyz`

The Render service hosts only the API. A separate frontend hosting and routing setup is needed before shop URLs such as `https://<slug>.sabrey.xyz` display menus. Configure the frontend and API routing together so API requests retain the shop hostname, then follow the hosting provider's wildcard DNS and TLS instructions. Review any existing `sabrey.xyz` records before changing them. Generate and test a shop QR code only after the public shop URL is working.

References: [Render wildcard custom domains](https://render.com/docs/custom-domains#using-a-wildcard-domain), [Render and Cloudflare DNS](https://render.com/docs/configure-cloudflare-dns), [Cloudflare wildcard DNS](https://developers.cloudflare.com/dns/manage-dns-records/reference/wildcard-dns-records/), and [Render free service limitations](https://render.com/docs/free). Render Free can stop after inactivity and take time to wake up; it is intended for testing, not a reliable production service.
